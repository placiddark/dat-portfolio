Coding for REAPER With ChatGPT

Start with a Lua script that creates a track. Then build a gain control and write prompts for the jobs you repeat in your own sessions.

Start the Guide

Set Up REAPER for Scripting

Install REAPER for your operating system and open a blank project. Note your REAPER version and operating system before you ask ChatGPT for code. In REAPER, use the Options menu to locate your resource folder. You’ll use its Effects folder later.

  • ReaScript lets you automate tracks, media items, MIDI and other project operations. Start with Lua, which REAPER includes. EEL2 is also built in. Python requires a separate setup.
  • JSFX uses EEL2 to process audio or MIDI in an FX chain.
  • Custom actions let you chain existing REAPER actions in the Action List.

See the ReaScript guide and API reference for function signatures.

Write and Run Your First Script

Give ChatGPT a starting state and an outcome you can check. Tell it which project objects the script may change and how you want Undo to work.

I use REAPER [version] on [OS]. Write a complete Lua ReaScript that appends one track called “Vox” to the active project. Leave existing tracks alone. Put the change in one undo step and print a confirmation to the ReaScript console. Add comments for the REAPER API calls and include a short test plan.

local project = 0 -- Active project
local index = reaper.CountTracks(project)

reaper.Undo_BeginBlock2(project)
reaper.InsertTrackAtIndex(index, true)
local track = reaper.GetTrack(project, index)
if track then
  reaper.GetSetMediaTrackInfo_String(track, "P_NAME", "Vox", true)
  reaper.ShowConsoleMsg("Created track: Vox\n")
end
reaper.Undo_EndBlock2(project, "Create Vox track", -1)
reaper.UpdateArrange()
  1. Open Actions → Show action list. Under New action, choose New ReaScript.
  2. Save it as create_vox_track.lua, paste the example into the editor and save again. Select the script in the Action List and run it.
  3. Check for one new track at the bottom and a console message. Undo once and check that the track disappears.

Debug From the Error Message

Give ChatGPT the exact error, the relevant code and the steps that triggered it. Ask for the smallest fix and a test. If REAPER reports a nil function, check the spelling and whether the function requires an extension. If a track or take is nil, check the project or selection before you pass the object to another API call.

Build Your First JSFX

This stereo gain control starts at 0 dB. Its bypass switch passes both channels through at their input levels. Save the code as simple_stereo_gain.jsfx in the REAPER resource folder’s Effects directory. Refresh or reopen the FX browser and search for Simple Stereo Gain.

desc:Simple Stereo Gain
slider1:0<-60,12,0.1>Gain (dB)
slider2:0<0,1,1{Off,On}>Bypass

@slider
gain = exp(log(10) * slider1 / 20);
bypassed = slider2;

@sample
!bypassed ? (
  spl0 *= gain;
  spl1 *= gain;
);

Play an audio item at a comfortable level. Set the gain to −6 dB and compare the meter with bypass off and on. As a next exercise, ask ChatGPT for a stereo width control with 0% for mono and 100% for the original stereo signal. Test it on a stereo file with distinct left and right content.

See the JSFX programming reference for effect structure and sample processing.

Build a Stereo Width Control

Save this second JSFX as simple_stereo_width.jsfx in the same Effects folder. It splits the stereo signal into a shared component and a difference component. The Width slider changes how much of the difference you hear.

desc:Simple Stereo Width
slider1:100<0,200,1>Width (%)
slider2:0<0,1,1{Off,On}>Mono

@slider
width = slider2 ? 0 : slider1 / 100;

@sample
mid = (spl0 + spl1) * 0.5;
side = (spl0 - spl1) * 0.5 * width;
spl0 = mid + side;
spl1 = mid - side;

At 100%, compare against bypass. At 0%, both channels should match. Turn Mono on and confirm the Width slider has no effect. Check your output peaks when you widen the signal above 100%.

Adapt These Prompts to Your Session

Replace bracketed values before you paste a prompt. Run edits in a scratch project first and check Undo where the script changes project state.

Batch Track Creation

Write a Lua ReaScript for REAPER [version] on [OS] that appends eight tracks named Vox 1 through Vox 8 and colours them red. Leave existing tracks and their routing alone. Put the changes in one undo step and tell me what happens if I run the script twice.

Custom Actions

Show me how to create a REAPER custom action that splits selected items at the edit cursor and selects the right-hand pieces. Tell me the exact Action List names to verify in my installation. Explain what happens if no selected item crosses the cursor.

MIDI Transposition

Write a Lua ReaScript that transposes selected notes in the active MIDI editor up seven semitones. Leave unselected notes alone. Skip notes that would exceed MIDI pitch 127, report how many you skipped and sort the take after the edits.

Track Creation With ReaImGui

I have ReaImGui [version] installed. Write a Lua ReaScript with a text field and a button that creates one named track per click. Reject an empty name, close cleanly and include a message if the extension is missing.

Region Rendering

Show me how to render project regions as separate WAV files named after each region in REAPER [version]. Handle duplicate region names and existing files. If you propose a script, have it show me the proposed output paths before it starts rendering.

Tempo Map Export

Write a Lua ReaScript that exports the active project’s tempo and time signature markers to JSON. Include each marker’s position in seconds, tempo in BPM, time signature and whether it starts a linear tempo transition. Ask me where to save the file and report file-write errors.

Track Folder and Routing

Write a Lua ReaScript that puts adjacent selected tracks in a new DRUMS folder. Explain how you will handle nested folders and preserve existing sends. If the selection cannot move without changing the surrounding folder structure, show a message before you edit.

FX Chain Recall

Show me how to save the selected track’s FX chain and load it on a duplicate track. Start with the built-in workflow and identify what you can automate from the Action List in my version.

Volume Automation

Write a Lua ReaScript that adds a volume envelope point at the edit cursor on the selected track. Keep the existing envelope shape and tell me what the script does if there is already a point at that time.

Bounce an Item to a New Take

Show me which REAPER action renders a selected item as a new take for my use case. Explain which FX it captures, what happens to the original take and how to check the result on a project copy.

Production Lab With OpenClaw and REAPER

Use the scripting exercises to build a short spoken-word piece. You can try the workflow yourself or assign the same brief to separate agents. In an OpenClaw setup, each role proposes a change. You review the proposal before a REAPER runner applies it. The example below describes the handoff for a runner you build and test.

Build eight bars at 68 BPM in 4/4. Start with a quiet 93 Hz drone, bring in an irregular rain bed and introduce a sparse MIDI figure at bar three. Keep the voice close and centred. Open the reverb on the last word and let it decay past the final bar.

Give Each Role a Specific Output

RoleWhat You Ask For
ComposerA MIDI figure and a cue sheet with entries and rests.
Sound DesignerDrone settings, a rain texture and a proposed reverb send.
Mix EngineerA timestamped listening note and one adjustment to test.
LyricistBreath marks, word stresses and an alternate reading of your phrase.
ProducerA change list for the next pass and a reason for each edit.

Route the Session

If you want to recreate the full template, use these 13 track roles. Keep reference takes and score data out of the production mix.

TracksPurpose
01–02Brief and muted scratch read; optional analysis feed with its master send off.
03–04Drone; pre-master mix bus.
05–06Rain bed with its own automation; muted MIDI score reference.
07–08Selected vocal take; print bus that feeds the REAPER master.
09–10MIDI instrument; wet FX return.
11–13Muted A/B references; muted alternate takes; revision notes and markers.

Send the drone, rain, vocal, MIDI instrument and wet return to the pre-master. Send the vocal separately to the wet return. Route the pre-master to the print bus and disable direct master sends on the sources, return and pre-master. If you use the analysis feed, give it a send from the pre-master and keep it out of the print path. Compare the finished WAV to hear the print-bus processing.

Score the Eight Bars

BarsArrangementWhat to Hear
1–2Start with the drone. Add a few rain events in bar two.Listen for silence between rain events.
3–4Introduce a short figure and lower the rain just before the voice enters.Keep a gap at the end of the figure for the first breath.
5–6Read the first two parts of your phrase over the drone. Keep the lead vocal dry and centred.Make sure you can hear consonants where the figure and voice overlap.
7–8Raise the wet send during the last word’s vowel. Drop the MIDI figure in bar eight.Listen for the complete word and let the room decay after it.

Eight bars run about 28 seconds at this tempo before the tail. Record two readings over the same backing so you can compare phrasing without a change in the arrangement.

Approve the Handoff Before REAPER Applies It

Have OpenClaw collect proposals in plain language. Record your approved edits in a manifest. Keep the Lua runner limited to defined operations such as importing MIDI, adjusting a send and saving a project copy. Resolve tracks by GUID so a display-name change does not redirect an edit.

Base project     Sketch_v001.rpp
New revision     Sketch_v002.rpp
Required assets  figure.mid, rain.wav, voice_take_02.wav
Approved edit    Place the chosen take at bar 5
Approved edit    Raise the vocal reverb send on the last vowel
Render           Sketch_v002_review.wav, bars 1–8 plus decay
Approval         Review the manifest before applying the edits

Check the base revision, track IDs, source files and required plug-ins before you apply changes. If a plug-in is missing, choose a substitute or request a printed stem. Save a new project revision for each pass and give its review WAV the same version number.

Compare Two Passes at the Same Playback Level

Keep the voice take fixed and change one production choice. If the MIDI attack masks a word in bar six, move that attack into the preceding breath and render again. If the rain obscures a consonant, try a short dip under the phrase. If the tail cuts off, extend the render boundary and check the last few seconds. Keep a timestamped listening note with each version. Log peak level, integrated loudness and clipping indicators when your meter provides them.

Extend the Sketch and Export a Visual Score

Use bars 9–16 to add density while the voice rests. Pull the rain and most of the drone back in bars 17–24 and leave a fragment of speech exposed. Bring back the full phrase in bars 25–32 and let the final decay run past the boundary. At 68 BPM in 4/4, 32 bars run about 1 minute 53 seconds before the tail.

For an optional score visual, use a muted MIDI track for note events and project markers for vocal cues. Map note onsets to when shapes appear, durations to how long they stay and velocity to brightness. Hold the final shape through the reverb tail. Save the cue map with the project so you can render it again after an edit.

Use the Same Method in Another DAW

Choose the host’s scripting tool for the job. For example, you can work with a Max for Live device in Ableton Live, a Scripter MIDI effect in Logic Pro or Lua session scripts in Ardour. Give ChatGPT the host version and relevant API documentation so it can draft code for that environment.

I use [DAW and version] on [OS]. I want to [describe the task] using [scripting tool or API]. Here’s the starting state [describe the project or selection]. The script can change [scope]. Return the code, installation steps and a test I can run on a project copy. Flag any dependencies or API calls I need to verify.

For REAPER examples and packages, see ReaPack, the REAPER Stash and the Cockos forum.

Adapt a Script You Can Maintain

Read the source and licence before you adapt a community script. Start with one small change and keep a copy you can compare. Document what the script expects, what it changes and which dependencies you need before you share it. The ReaTeam script collection and SWS Extension are starting points for further work.

Finish With a Print You Can Recreate

  1. Play the approved WAV from the first audible sample through the end of the tail. Confirm the words you want the listener to catch are clear.
  2. Verify the render range, file name and any embedded credits. Keep the final WAV beside the project revision that produced it.
  3. Archive the project, source assets, approved manifest and any cue map. Reopen the saved project and check that its media and plug-ins resolve.

Your first finished exercise can be just eight bars. When you can hear the whole phrase, the rain has its own space and the tail decays naturally, keep that WAV as the reference for the full track.
