Harmonic Scaffold

A framework for defining what an AI-generated draft must contain, checking it against explicit rules and recording why it passed or went back for revision.

Harmonic Scaffold began as a project for an unnamed organisation focused on starseed pre-natal astrology. The project took shape in The Book of the Harmonic Scafflod, a conceptual treatise on framework design and ritual grammar. This showcase adapts its methods for defining rules, checking sequences and recording completion to AI workflows.

From Brief to Auditable Output

The Scaffold borrows the sequence and record-keeping of ritual grammar. A workflow specifies the conditions for each step, records which steps ran and defines what must happen before the output can move forward.

Resonance Pattern

Define the Expected Shape

Pair a versioned prompt with an output contract and examples. A brief may call for a headline and summary with set length limits. Different generations can satisfy the same contract.

Audit Gate

Give Every Check a Result

Define a condition and what happens if it fails. A draft with a missing field goes back for revision with the field named. Use editorial review for decisions that need judgement.

Cascade

Check Prerequisites First

Parse the draft before checking its fields. Confirm the fields before applying content rules. When a prerequisite fails, record the remaining checks as skipped and rerun the full sequence after revision.

Deterministic Seal

Mark What Passed

Issue a completion marker against the rule version that accepted the draft. In a production record, link that marker to the accepted output and the evidence from its run. The marker attests to the checks that ran.

Audit a Short Landing Page Draft

Try five patterns drawn from a landing-page audit checklist. Each pattern defines what the draft must contain and which rule it must pass. The Harmonic Scaffold checks the JSON first, validates the fields next and applies the selected copy rule last.

Choose a pattern and run its draft. The report shows the first failed gate, any checks that were skipped and what to revise. Edit the JSON yourself or load the revised sample and run it again. A clean run issues a completion marker tied to the selected ruleset.

Inside the Treatise

The source outline describes a 682-page-equivalent conceptual work. The volume ranges below follow that outline. This showcase adapts its central pattern, gate and completion logic for an AI workflow.

Volumes I–XVII

AI Workflow Architecture

Specify prompt constraints, review steps and exit conditions. Each volume uses a common template with a principle, evidence, examples, exceptions and a checkpoint.

Volumes XVIII–XXXIV

Ritual Grammar

Define the run record. Capture the input reference, expected pattern, checks attempted, decisions and any completion marker or reset state.

Volumes XXXV–XLVII

Signature and Completion Registers

Link an accepted artifact to its run, rule version and gate history. The register gives a reviewer a way to trace a release decision back to the rules in force at the time.

Volumes XLVIII–682

Comparative Workflow Cases

Apply the same record structure to AI systems, benchmark tasks and publication pipelines. Compare which checks transfer and which need rules of their own.

Where the Scaffold Fits

Content and Publishing

Check required fields and house rules before an editor reviews claims and approves the draft. Record both decisions with the accepted revision.

Code Generation

Check the generated change with linting and relevant tests, then record the review decision against the same version of the change.

Extraction and Classification

Validate field types and allowed labels. Route missing evidence or ambiguous cases to a reviewer and retain the source reference.

Workflow Training

Give learners a sample input, an acceptance contract and a failed run. Ask them to revise the draft and explain the evidence behind the next decision.

What the Next Run Inherits

Retain the versioned rules and prior run records. Start the next input with a fresh run ID and empty review state. If a draft fails, keep that record with its revision reason so the next attempt has a traceable starting point.

Minimum Run Record
Run and input references, prompt and rule versions, expected output pattern, gate results, final disposition and any completion marker.
